## Contract history and per-record documents

The three Northstar contracts model a multi-year relationship with the same customer. Each contract links to its own Opportunity, and the document is uploaded into that **Opportunity's** Box folder by `seed-clm-contract-files.apex` (via `BoxEmailAttachmentUploader`) — Opportunity is the Box-mapped object:

| Record | Status | File (in the contract's Opportunity Box folder) | Static resource |
|---|---|---|---|
| `CLM-SAMPLE-NST-2024` | Executed | `northstar-msa-2024-executed.pdf` | `Clm_Sample_Msa_2024_Executed` |
| `CLM-SAMPLE-NST-2025` | Executed | `northstar-msa-2025-executed.pdf` | `Clm_Sample_Msa_2025_Executed` |
| `CLM-SAMPLE-NST-001` (2026) | Legal Review | `northstar-msa-2026-redline.docx` (Word — still redlining) | `Clm_Sample_Msa_2026_Redline` |

Prior years get the **executed PDF**; the current year gets the in-redline **Word** document. Assets are generated by `scripts/generate_sample_contract_assets.py` (PDFs) and `scripts/generate_docgen_templates.py` (the redline docx). The upload targets the contract's **Opportunity** Box folder (Opportunity is the Box-mapped object; `CLM_Contract__c` is not, so each contract carries its own Opportunity).

## Relationships populated

- `CLM_Contract__c.Counterparty_Account__c` references `Account` (all three Northstar contracts point at the same Northstar Health account).
- `CLM_Contract__c.Opportunity__c` references `Opportunity` — every Northstar contract links to its own per-year Opportunity (2024, 2025, 2026), which is what carries the Box folder the document lands in.
- Opportunities are related to their owning Accounts.
- Contacts are related to their owning Accounts.

## Seed behavior

- **Idempotent and rerunnable**
  - Accounts by `Name`
  - Contacts by `Email`
  - Opportunities by `Name` + `AccountId`
  - Contracts by `Contract_ID__c`
- Existing records are updated with required relationship fields so links stay aligned.
- Missing records are created.

## Files

- `clm-sample-records.bcl` — descriptive sample-record spec in the repository's BCL format. Mirrors the Apex values for packaging; it is not read at seed time.
- `../scripts/seed-clm-salesforce-sample-data.apex` — Apex executable and source of truth for the records.
- `../scripts/seed-clm-sample-data.sh` — `sf` wrapper for the records seed.
- `../scripts/seed-clm-contract-files.apex` — uploads each contract's document into its Box record folder.
- `../scripts/seed-clm-contract-files.sh` — `sf` wrapper for the file upload.

## Run

Seed records, deploy the contract-file static resources, then upload the files into each record's Box folder:

```bash
# 1. records
./scripts/seed-clm-sample-data.sh agentforce
# 2. deploy the static resources (once)
sf project deploy start --target-org agentforce --source-dir force-app/main/default/staticresources
# 3. upload each contract's document into its Box record folder
./scripts/seed-clm-contract-files.sh agentforce
```

Optional: to also populate the shared **06 - Executed Agreement** Box folder (the App's Executed Agreements view), add the executed PDFs to `scripts/demo_operator.py` `UPLOADS`.
