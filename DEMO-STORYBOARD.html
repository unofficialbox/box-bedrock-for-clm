CLM Demo Storyboard

The counterparty uploads their redline in their own portal, and it is read against the approved clause library and the two agreements they have already signed. Six beats on one account, two windows, every prompt below is copy-paste.

Bind before use. The site URL and the counterparty login below are placeholders; substitute the values for the environment you are presenting from. Everything else -- prompts, contract references, expected answers -- is portable.

Preflight

Four checks before anyone is watching. P4 and P5 are one-time setup, already done — they stay here because a rebuilt org needs them again.

P1

bash

P2
Claude Desktop

Set the answer length

Claude Desktop decides how long an answer is, and it defaults to an essay — the beat 4 precedent question comes back as roughly 500 words and three tables. Nothing on the Salesforce side changes that: a hosted MCP server exposes tool descriptions, not a response style. Put this in the project’s custom instructions before you present, and run the beats inside that project. A fresh chat outside it carries none of these rules, and the difference is stark: the same beat 3 question answers in 60 words inside the project and in roughly 400, with tables and a closing offer, outside it.

instruction
Answer in 60 words or fewer unless I ask for more. Lead with the finding. No preamble, no restating my question, no narrating which tool you called. Never print Box file IDs, folder IDs or Salesforce record IDs - use them, do not show them. Never decline a governed action on my behalf or predict that it will fail: call it and report what it says. Offer at most one follow-up, in one line. At most one table, only when comparing the same clause across contracts. Cite each source file once, as a link, at the end. No closing offers.
Expect beat 4 to answer in a short paragraph and one table, not a briefing note.
P3
Claude Desktop

Connect both connectors, and refresh the CLM one

The Box connector must be on as well as the CLM one. Beat 1 previews the customer paper and beat 2 searches Box metadata; neither is possible with only the CLM tools loaded. Then the CLM one: it had three tools when you first connected it and now has five. Open Settings → Connectors, find the CLM connector, disconnect and reconnect it. Don't retype the endpoint — reuse the one already configured.

Expect both connectors listed under Context in the session, not merely enabled in Settings — a project with only CLM loaded cannot preview a document, and beat 1 falls back to reading file IDs aloud. Six CLM tools: listContracts, findDocumentsByRisk, getContractPackage, askContractDocument, generateCounterPosition, sendSignatureRequest. Beat 5 needs the last two.

The six beats

Beat 1 is a private browser window — the counterparty's own portal, where the paper actually arrives. Beats 2 through 6 run in Claude Desktop against both connectors: CLM for the contract data, Box for previews and metadata search. One account carries the whole story, start to finish — Northstar Health.

Private browser window

Their paper arrives, from their side

url
https://<your-site>.my.site.com/clmvforcesite/login?startURL=%2Fclm%2F

Sign in as Dana Whitfield, Northstar's counsel. The password is the one set in P6.

Go to the login path, not the app path. /clm/ serves the app for every URL beneath it — /clm/login and /clm/s/login/ both render the workspace rather than a sign-in page, and a signed-out visitor is never redirected. The login page lives on the other path prefix, /clmvforcesite/login; startURL returns you to the workspace after.
Expect the header to name her — Dana Whitfield · Northstar Health — above four Northstar contracts and no Calder or Halcyon. Same code, different identity, different rows — enforced by a Salesforce sharing set on the counterparty account, with the Box token downscoped to one folder.

Now do the thing the whole demo hangs on. Open Northstar Health Master Agreement 2026 and upload their redline: output/pdf/northstar-msa-redline-v4.pdf. This is the counterparty sending their paper, on their own login, into a folder they can reach and no other counterparty can.

Expect the upload to land in the contract's governed Box folder and appear in the document list without a page reload. Nobody emailed an attachment, and nobody on our side filed it — which is why the next beat can start from “it is already here”.
There is no Copilot on this page. It ran as its own agent user rather than as Dana and took the contract name from the conversation, so it could be asked about another company's contract — a scoped workspace around an unscoped agent. It was removed from the external app rather than left for someone to find.

Point at the name before you leave. The page states who it is scoped to, so the scoping is shown rather than asserted. Open a contract and the workspace lists fewer documents than the internal package does: the redlines are withheld by metadata, not by a different folder.

Claude Desktop

We pick it up on our side

prompt
Show me the Northstar master agreement that is still in legal review, then open a preview of the redline they just sent.

Switch windows and say the line that sets up everything after it: nobody forwarded this, nobody filed it. It is the same document Dana uploaded a minute ago, now in front of the team that has to answer it.

The preview is the beat. The package listing is only the means to it — Box file IDs are plumbing and mean nothing to a room, so let the document carry the point instead of reading a list aloud.

345 sec
Claude Desktop

The portfolio already knows what's risky

Uses the Box connector, enabled in P3.

prompt
Which contract documents across the portfolio are flagged critical risk?
Expect two files, on two different papers — northstar-msa-redline-v4.pdf, the one just uploaded, and calder-msa-customer-paper-v2.pdf from an unrelated account. The flag was applied when the document landed, not when someone asked.
Give it the folder id, not the folder name. Box metadata search is enterprise-wide, and this enterprise still holds documents from earlier demo environments with the same file names and different IDs. Naming the folder does not scope it either: searching Box for “CLM Root” returns CLM, CLM Build and two CLM Instructions folders, and not the one you mean. The ancestor_folder_id is the only thing that actually bounds the query. To an audience, an unscoped search reads as the wrong account appearing.
A freshly moved or uploaded file takes a few minutes to appear here. Box reindexes metadata after the fact, so a document uploaded in beat 1 may not be searchable by the time you reach this beat. Upload it during setup if the run is tight.
490 sec
Claude Desktop

Read it against our approved positions

The beat the demo exists for.

prompt
Where is our liability exposure in Northstar's redline, and how does it compare to our approved clause library? Cite the file and the clause IDs.
Expect the redline to have deleted the cap, not argued about it: the fee-based limit and the two-times cap for data and security breaches are struck from 15.1–15.3 and replaced with unlimited liability for direct and indirect damages. Approved position CLM-LIAB-001 is twelve months of fees; fallback CLM-LIAB-002 is twenty-four; uncapped is not an approved position, and Commercial Legal owns the deviation.

Land it: a template diff cannot find this, because the change is a deletion — the clause that would fail the diff is simply gone. Only reading the document against a governed library catches an exposure that is defined by absence.

545 sec
Claude Desktop

What they agreed the last two times

prompt
Compare the liability cap across the two Northstar agreements we have already executed and this 2026 redline. What did they actually agree before, and does the redline match it?
Expect a fee-based cap in both executed agreements — the 2024 states twelve months of fees under the affected order form, at its Limitation of Liability clause — against a 2026 redline that removes the cap altogether.

Land it: Northstar is not asking for something new. They signed a twelve-month cap twice, and their redline now deletes the clause they signed. That is a course-of-dealing argument, and it is the one that moves a negotiation.

660 sec
Claude Desktop

Put the position on paper, then stop

prompt
Draft the counter-position memo for this Northstar agreement, using the approved fallback and the precedent from the executed agreements.
Doc Gen is asynchronous. The reply says “submitted” and the PDF lands a few seconds later. Have the Northstar Box folder open in a tab and refresh it rather than waiting on the chat.

Show the memo: clause at issue, what their redline says, the approved fallback, Commercial Legal as owner, the precedent, the proposed counter-position. Nothing on that page was typed. Then show the boundary:

prompt
Send Northstar's 2026 master agreement for signature.
Expect the action to be called, and to come back refusing, naming Legal Review. That is a state check in Apex, not a prompt instruction.
If the assistant declines without calling the action, the beat has not happened. A model that reasons “this would fail anyway” and offers alternatives is making a prompt-level refusal look like a control — the opposite of the point. Say “call it anyway and show me what it returns”. The P2 instruction tells it not to pre-judge, so this should be rare.

Then show it working. The refusal is the control; a demo that only ever refuses has not shown the step. The same counterparty has a package already through review, so the same action goes through against it.

prompt
Now send the approved Northstar MSA package for signature.
Expect the request to go out, addressed to the configured demo signer. Nobody types a signer: the action falls back to CLM_Box_Config__c.Demo_Signer_Email__c, so a demo does not stall on “who is signing?” and no address lives in source. Box places the signature block itself, so there is no prepare-and-place detour out of the conversation.
Then open the contract record in Salesforce. The request is on it, under Box Sign Requests. The action goes through the Box managed package rather than calling Box directly, which is what writes that row and links it — the paper trail lands where the deal is managed, not only inside Box. It closes the loop Dana opened in beat 1, on the same account.

If someone asks

Three things to answer honestly

  • Doc Gen and Sign are real; write-back isn't. Box Doc Gen writes the memo into the governed folder and Box Sign prepares a request. Nothing updates the Salesforce contract record — that's the next thing to build.
  • The Copilot was removed from the counterparty site, not scoped. It's a Service Agent, which runs as its assigned agent user, so it could not inherit Dana's access. An Employee Agent inherits the signed-in user's permissions instead; that's the surface where "same agent, different access" would hold, and it's where the internal Copilot runs.
  • The metadata tagging is manual. A metadata cascade policy on the contract folder is what would make it survive the next contract. Today it's applied by hand.
