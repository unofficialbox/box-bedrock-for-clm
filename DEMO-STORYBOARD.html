A deal on the customer's paper, read against the approved clause library and the two agreements Calder already signed. Six beats, two windows, every prompt below is copy-paste.

Bind before use. The site URL and the counterparty login below are placeholders; substitute the values for the environment you are presenting from. Everything else -- prompts, contract references, expected answers -- is portable.

Preflight

Four checks before anyone is watching. P4 and P5 are one-time setup, already done — they stay here because a rebuilt org needs them again.

P1

P2
Claude Desktop

Set the answer length

Claude Desktop decides how long an answer is, and it defaults to an essay — the beat 4 precedent question comes back as roughly 500 words and three tables. Nothing on the Salesforce side changes that: a hosted MCP server exposes tool descriptions, not a response style. Put this in the project’s custom instructions before you present, and run the beats inside that project. A fresh chat outside it carries none of these rules, and the difference is stark: the same beat 3 question answers in 60 words inside the project and in roughly 400, with tables and a closing offer, outside it.

instruction
Answer in 60 words or fewer unless I ask for more. Lead with the finding. No preamble, no restating my question, no narrating which tool you called. Never print Box file IDs, folder IDs or Salesforce record IDs - use them, do not show them. Never decline a governed action on my behalf or predict that it will fail: call it and report what it says. Offer at most one follow-up, in one line. At most one table, only when comparing the same clause across contracts. Cite each source file once, as a link, at the end. No closing offers.
Expect beat 4 to answer in a short paragraph and one table, not a briefing note.
P3
Claude Desktop

Connect both connectors, and refresh the CLM one

The Box connector must be on as well as the CLM one. Beat 1 previews the customer paper and beat 2 searches Box metadata; neither is possible with only the CLM tools loaded. Then the CLM one: it had three tools when you first connected it and now has five. Open Settings → Connectors, find the CLM connector, disconnect and reconnect it. Don't retype the endpoint — reuse the one already configured.

Expect both connectors listed under Context in the session, not merely enabled in Settings — a project with only CLM loaded cannot preview a document, and beat 1 falls back to reading file IDs aloud. Six CLM tools: listContracts, findDocumentsByRisk, getContractPackage, askContractDocument, generateCounterPosition, sendSignatureRequest. Beat 5 needs the last two.

The six beats

Beats 1 through 5 run in Claude Desktop against both connectors — CLM for the contract data, Box for previews and metadata search. Beat 6 is a private browser window.

145 sec
Claude Desktop

Their paper arrives

prompt
Show me Calder Financial Group's master agreement that is still in legal review, then open a preview of the customer paper.

Point at calder-msa-customer-paper-v2.pdf. Say the line that sets up everything after it: Calder doesn't accept supplier paper, so this is the document being negotiated — and there is no Limitation of Liability section anywhere in it.

The preview is the beat. The package listing is only the means to it — Box file IDs are plumbing and mean nothing to a room, so let the document carry the point instead of reading a list aloud.

245 sec
Claude Desktop

The portfolio already knows what's risky

Uses the Box connector, enabled in P3.

prompt
Which contract documents across the portfolio are flagged critical risk?
Expect exactly two files, on two different papers: northstar-msa-redline-v4.pdf and calder-msa-customer-paper-v2.pdf.
Give it the folder id, not the folder name. Box metadata search is enterprise-wide, and this enterprise still holds documents from earlier demo environments with the same file names and different IDs. Naming the folder does not scope it either: searching Box for “CLM Root” returns CLM, CLM Build and two CLM Instructions folders, and not the one you mean. The ancestor_folder_id is the only thing that actually bounds the query. Box metadata is enterprise-wide, so an unscoped search also returns documents from earlier demo environments — same file names, different IDs, folders that aren't governed contract folders. To an audience that reads as the wrong account appearing.
390 sec
Claude Desktop

Read it against our approved positions

The beat the demo exists for.

prompt
Where is our liability exposure in Calder's customer paper, and how does it compare to our approved clause library? Cite the file and the clause IDs.
Expect exposure at 19.2 and 22.4; approved position CLM-LIAB-001 (12 months); fallback CLM-LIAB-002 (24 months); uncapped is not an approved position; Commercial Legal owns the deviation.

Land it: a template diff can't find this — there's no Acme template to diff against. A keyword search for "limitation of liability" returns nothing, because the phrase doesn't appear. Only reading it against a governed library does.

445 sec
Claude Desktop

What they agreed the last two times

prompt
Compare clause 22.4 and clause 19.2 across the two Calder agreements we have already executed and this 2026 draft. What did Calder actually agree before, and does the draft match it?
Expect both prior agreements carry a negotiated 24-month aggregate cap, recorded in a Schedule 1 of agreed amendments to Calder's own standard form — and the 2026 draft restores the unamended house text of both clauses.

Land it: Calder isn't asking for something new. Their template regressed two positions their own legal team conceded, in writing, twice. That's a course-of-dealing argument, and it's the one that moves a negotiation.

560 sec
Claude Desktop

Put the position on paper, then stop

prompt
Draft the counter-position memo for this Calder agreement, using the approved fallback and the precedent from the executed agreements.
Doc Gen is asynchronous. The reply says "submitted" and the PDF lands a few seconds later. Have the Calder Box folder open in a tab and refresh it rather than waiting on the chat.

Show the memo: clause at issue, what their draft says, the approved fallback, Commercial Legal as owner, the precedent, the proposed counter-position. Nothing on that page was typed. Then show the boundary:

prompt
Send the Calder agreement for signature.
Expect the action to be called, and to come back refusing, naming Legal Review. That's a state check in Apex, not a prompt instruction — and once the contract is approved, the action still only prepares the request and hands back a URL for a person to send.
If the assistant declines without calling the action, the beat has not happened. A model that reasons "this would fail anyway" and offers alternatives is making a prompt-level refusal look like a control — the opposite of the point. Say “call it anyway and show me what it returns”. The P2 instruction tells it not to pre-judge, so this should be rare.

Then show it working. The refusal is the control; a demo that only ever refuses has not shown the step. CLM-2026-0017 is Approved and carries documents, so the same action prepares against it.

prompt
Now prepare the Northstar MSA package for signature.
Expect the request to go out, addressed to the configured demo signer. Nobody types a signer: the action falls back to CLM_Box_Config__c.Demo_Signer_Email__c, so a demo does not stall on “who is signing?” and no address lives in source. Box places the signature block itself, so there is no prepare-and-place detour out of the conversation.
Then open the contract record in Salesforce. The request is on it, under Box Sign Requests. The action goes through the Box managed package rather than calling Box directly, which is what writes that row and links it — the paper trail lands where the deal is managed, not only inside Box.

Private browser window

The same platform, scoped to the other side

url
https://<your-site>.my.site.com/clmvforcesite/login?startURL=%2Fclm%2F

Sign in as Dana Whitfield. The password is the one set in P5.

Go to the login path, not the app path. /clm/ serves the app for every URL beneath it — /clm/login and /clm/s/login/ both render the workspace rather than a sign-in page, and a signed-out visitor is never redirected. The login page lives on the other path prefix, /clmvforcesite/login; startURL returns you to the workspace after.
Expect the header to name her — Dana Whitfield · Northstar Health — above four Northstar contracts and no Calder or Halcyon. $7.1M total on the value chart, two renewals inside 90 days. Same code, different identity, different rows — enforced by a Salesforce sharing set on the counterparty account, with the Box token downscoped to one folder.

Point at the name. The page states who it is scoped to, so the scoping is shown rather than asserted — that is the whole beat. Open a contract afterwards and the workspace lists five documents where the internal package lists seven: the redlines are withheld by metadata, not by a different folder.

There is no Copilot on this page any more. It ran as its own agent user rather than as Dana and took the contract name from the conversation, so it could be asked about another company's contract — a scoped workspace around an unscoped agent. It was removed from the external app rather than left for someone to find.

If someone asks

Three things to answer honestly

  • Doc Gen and Sign are real; write-back isn't. Box Doc Gen writes the memo into the governed folder and Box Sign prepares a request. Nothing updates the Salesforce contract record — that's the next thing to build.
  • The Copilot was removed from the counterparty site, not scoped. It's a Service Agent, which runs as its assigned agent user, so it could not inherit Dana's access. An Employee Agent inherits the signed-in user's permissions instead; that's the surface where "same agent, different access" would hold, and it's where the internal Copilot runs.
  • The metadata tagging is manual. A metadata cascade policy on the contract folder is what would make it survive the next contract. Today it's applied by hand.
